## Proposed v0.4 architecture

Start with one host-registered fetch service, using `shivax.hanuman.fetch` as the proposed tool ID and `hanuman.fetch` as the proposed capability. Put the registration helper and transport contract in `shivax/integrations`. Route through `RudraWorkflowEngine` and its existing `ToolRegistry.bind()` seam. This reaches real protected execution without adding any of the future bots or changing default bot discovery. The names and role split below are H00 design decisions. The current source has no HANUMAN, Abhimanyu, Ashwatthama, Jambavan, or Kubera contracts.

1. The host supplies a target table of named, fixed HTTPS URLs and a trusted transport capable of enforcing its egress contract. Freeze validated target and limit configuration at registration. A host explicitly binds this service in its workflow registry, allows the capability for that run, grants the exact tool ID in the Jay context, and configures Vijay policies and a NARASIMHA protected operation. The default SDK and specialist factory perform no additional registration, DNS, or network I/O.
2. A fetch action takes `{ targetId: string }`. Version 0.4 starts with a fixed GET method and a bounded plain-text or JSON response, with JSON returned as inert text. Callers supply no raw URLs, headers, credentials, query parameters, request bodies, redirect settings, deadlines or budgets. The host approves the target for the authenticated scope. Configure the tool policy as `read-only` with `requiresApproval: true`, and verify that the underlying use case is a read. Configure workflow retries to zero and bind the tool as sequential for its first release.
3. The protected implementation receives the leased `ToolExecutionContext`. Require both the live `checkExecution` and `checkNetworkAccess` callbacks. Check execution and the canonical destination before any resolver or connector call, and checkpoint again after resolution and immediately before connecting. A bound NARASIMHA tool operation must match exactly once for capability, effect and tool ID. The tool uses the signal delivered by Vijay, with a narrower host deadline when configured. Missing protection or policy fails closed before the transport is called. [Workflow dispatch](../../src/workflows/engine.ts), [Vijay tool path](../../src/security/vijay.ts), [lease context](../../src/security/tools.ts), [firewall binding](../../src/security/firewall/runtime.ts)
4. The host transport disables redirects, credential forwarding and cookie handling. Any proxy must be explicitly configured by the host. Accept only successful responses of the supported content types. Check limits before allocation and while reading, including decompressed bytes and the final encoded `BotValue` envelope. Close or drain the stream on every exit, aborting on failure or cancellation. Return a JSON-compatible envelope with `version: 1`, target ID, status, media type, body, and `trust: 'untrusted'`. Keep response headers, raw request URLs and raw transport exceptions out of projected metadata and logs. The workflow adds its normal untrusted wrapper.

## Security boundaries and regression risks

| Risk | Boundary and release requirement |
| --- | --- |
| Unapproved egress or authority injection | Sign-in, exact root context, explicit tool grant, capability allowlist, Vijay capability and tool policies, approval and mandatory firewall allow all stand independently. Tool input and upstream output are data. Keep fetch out of default planners, routing advice, model fallback and direct public execution helpers. An approved operation permits a named target for that run. Keep URLs, bodies, secrets and raw errors out of SDK audit events. |
| SSRF, rebinding, redirects and resolver discrepancies | NARASIMHA's callback checks HTTP(S) scheme, credentials and exact declared origin. It cannot observe the connected socket. The trusted transport must reject private, loopback, link-local, metadata, multicast and other non-public addresses including IPv4-mapped IPv6, verify IPv4/IPv6 DNS answers, pin a vetted destination through connection, preserve hostname/TLS verification, and enforce host/proxy egress. Block all redirects in the first release. Reject credentialed, non-HTTPS or deceptive canonical targets at registration. Browser code can consume a protected host broker only when that broker owns these checks. [Origin check](../../src/security/firewall/runtime.ts), [host boundary](../../SECURITY.md) |
| Revocation, cancellation and stale approvals | Reuse Vijay's post-approval verification and NARASIMHA's live checks. Jay stores grant snapshots and verifies provider revocation asynchronously at admission and approval. Have the host propagate in-flight session revocation through an abort signal or a revocation mechanism it controls. The transport must honor abort across DNS, connect, headers and body. SDK execution retains ownership until pending work settles, so a non-cooperative transport can delay cleanup. [Jay](../../src/security/jay.ts), [Vijay](../../src/security/vijay.ts), [lease draining](../../src/security/tools.ts), [session contract](../jay-vijay-security.md) |
| Resource exhaustion and concurrent admission | Enforce connection/read deadlines and cap wire and decoded bytes before buffering. Include serialized envelope overhead and cumulative workflow output limits. A bound single-tool workflow can hold a task lease plus two tool-operation leases through capability and tool authorization. Size firewall operation/concurrency limits for those leases, then test low limits and competing runs. Keep fetch-specific budget counters scoped to the applicable host run/realm. [Authorization](../../src/security/vijay.ts), [resource accounting](../../src/security/firewall/runtime.ts), [workflow limits](../../src/workflows/engine.ts) |
| Route and retry regressions | The workflow engine selects the first registered binding by tool ID for a capability, and RUDRA's default similarly orders bots by ID. Use a distinct capability and enforce one fetch binding in host composition. The firewall rejects zero or multiple matching descriptors. Generic read-only tool errors can retry when the host enables retries. Use zero retries in the initial fetch workflow and surface policy, validation and budget failures with terminal existing error categories. [Workflow bindings](../../src/workflows/registry.ts), [engine](../../src/workflows/engine.ts), [RUDRA selection](../../src/agents/rudra/orchestrator.ts) |
| Prompt injection and unintended retention | Render or process bodies as inert data. Preserve untrusted provenance downstream and keep body content out of logging, authority fields, memory hooks and learning ingestion. If a host opts into persistence or model input, require its existing scope, privacy and governance controls. [Workflow outputs](../../src/workflows/engine.ts), [SARASWATI governance](../../src/learning/provenance.ts) |
| Package and downstream compatibility | Catch manifest/exported version drift, existing API or bot ID removal, split root/subpath class identities, ambient DOM/Node declaration dependencies, changes to worker loading, and optional-peer regressions. Re-run packed consumers without Inspectra and preserve the historical C01 matrix as a release comparison. [Package tests](../../tests/package.test.mjs), [SDK tests](../../tests/sdk.test.mjs), [C01 audit](shivax-inspectra-c01.md) |
